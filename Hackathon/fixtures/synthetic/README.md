# Synthetic fixtures

Everything here is invented. No record corresponds to a real person.

- `fixtures.json` is generated by `clinical_triage.fixtures.render_fixture_json()`
  and must match it byte for byte (enforced by
  `tests/fixtures/test_synthetic_fixtures.py`). Regenerate after changing
  `src/clinical_triage/fixtures/synthetic.py`:

  ```bash
  uv run --frozen python -c "from pathlib import Path; from clinical_triage.fixtures import render_fixture_json; Path('fixtures/synthetic/fixtures.json').write_text(render_fixture_json(), newline='\n')"
  ```

- Guards: family name is always `Synthetic`, phones are fictional `555-01xx`,
  IDs are `SYN-PAT-A`..`SYN-PAT-G`, and clinical codes use `urn:synthetic:*`
  systems so they cannot be mistaken for real clinical coding.
- Slots are offsets from a fixed clock (`2026-10-05T12:00:00Z`) so every run is
  identical.

| ID | Scenario it supports |
| --- | --- |
| SYN-PAT-A | Routine request |
| SYN-PAT-B | Adaptive clarification |
| SYN-PAT-C | Urgent same-day |
| SYN-PAT-D | Emergency interruption |
| SYN-PAT-E | Human-review fallback |
| SYN-PAT-F | Scheduling failure / stale availability |
| SYN-PAT-G | Identity ambiguity (same name as A, different birth date) |

## Loading

- Offline: `clinical_triage.fixtures.SyntheticEHR` serves these fixtures through
  the provider-neutral EHR port, with deterministic fault injection.
- Local OpenEMR (opt-in, approval-gated): `infra/openemr/load_fixtures.py render`
  prints FHIR Patient documents; `apply` writes Patients only, requires
  `--apply --i-approve-local-synthetic-write`, a loopback URL, a pinned
  certificate, and `OPENEMR_ACCESS_TOKEN`, and skips patients already present.
  Writing needs a `user/Patient.c`-capable token, which is deliberately outside
  the read-only runtime adapter. Clinical codes and slots are not loaded into
  OpenEMR (no documented FHIR create path; OpenEMR has no FHIR `Slot`).
